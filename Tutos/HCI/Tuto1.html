HCI Tutorial 1: Introduction and History of HCI

How the UI affects the UX · Adaptation situations

Objectives

By the end of this tutorial, you should be able to:

  • Explain how UI problems (what users see and touch) harm the UX (effort, errors, frustration).
  • Classify an interface problem with the 12 problem types, say why it hurts the user and propose a concrete fix.
  • Audit a complicated interface: find the problems, and recognise the elements that are good.
  • Analyse a situation of use with the 4-step adaptation method: analyse, decide what to adapt, decide who triggers, check the risks.

Vocabulary · the 12 problem types

Use these categories to classify each problem you find.

Problem typePrincipleExample
1. Visibility of system statusThe system always tells the user what is happening.A student uploads an assignment and nothing changes for 10 seconds, so she clicks three times and submits three copies.
2. Match with the real world (clear language)Use the user's words, not the developer's.A postal app says "Transaction declined: code 05" instead of "Your balance is too low."
3. User control and freedomUsers can go back, cancel and undo.A payment wizard has no Back button: a typo on step 2 forces the customer to restart the whole payment.
4. Consistency and standardsThe same thing looks and works the same way everywhere.A date shown as 12/10 on one screen and "Oct 12" on another: is it 12 October or 10 December?
5. Error preventionDesign so that the error cannot happen, or is caught early.Submit stays disabled until the file is attached; "Delete my registration" asks for confirmation.
6. Recognition rather than recallShow options; do not make users remember them.A toolbar of unlabelled icons: the teacher must remember what each one does after a week away.
7. Flexibility and efficiencyFast paths for experts, simple paths for beginners.Searching one module among 212 in an unsorted list, instead of typing "HCI" in a search box.
8. Minimalist design (clutter, distraction)Every extra element competes with the task.A flashing "Special offer!" banner above an exam registration form.
9. Clear error messages and recoverySay what happened, why and what to do next, in plain words."File too large (max 10 MB). Compress it or choose another file." instead of "Error 500".
10. Help and documentationHelp is short, contextual and searchable.A tooltip next to "Student ID" explaining where to find the number, not an 84-page PDF.
11. Accessibility and readabilityEveryone can read and tap, in any situation.Light grey 9px text is unreadable on a phone in sunlight; red/green-only status is invisible to colour-blind users.
12. Visual hierarchyThe most important action looks the most important.On a payment page the big blue button says "Cancel" and "Pay" is plain text: users abandon by mistake.

Exercise 2 · Adaptation situations

For each situation, apply the 4-step method:

  1. Analyse the context, the task, the user characteristics and the technology. What varies?
  2. Decide what to adapt. Choose only what you can justify from your analysis.
  3. Decide who triggers the adaptation: the user (adaptable), the system (adaptive) or both (mixed).
  4. Check the risks: what if the system gets it wrong?

Possible adaptations

  • ☐ Light content (text/PDF instead of heavy video)
  • ☐ Hide secondary info
  • ☐ Download for offline use
  • ☐ Dark theme
  • ☐ Larger text
  • ☐ High contrast
  • ☐ Larger buttons / touch targets
  • ☐ Read-aloud / voice support
  • ☐ Simplify: one task per screen (guided)
  • ☐ Behaviour: draft saved, automatic retry, receipt after upload
  • ☐ Shortcuts / quick actions
  • ☐ Dense layout (progress, deadlines, grades)
  • ☐ Behaviour: personalise from usage
