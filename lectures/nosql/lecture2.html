1. Pourquoi NoSQL ?

1. Pourquoi NoSQL ?

Les bases relationnelles excellent sur les données structurées (transactions financières, gestion d’entreprise). Mais avec le Big Data, les réseaux sociaux et les applications mobiles, les volumes explosent et les données deviennent non structurées (images, vidéos, documents, flux temps réel).

Scalabilité verticaleAjouter CPU/RAM à un seul serveur : coûteux et limité.
Rigidité des schémasUn schéma fixe gère mal des données hétérogènes ou changeantes.
Relations et performancesLes jointures complexes sur des données massives ralentissent tout.
Réponse NoSQL : scalabilité horizontale (ajout de serveurs), flexibilité pour les données non structurées, performances pour les applications web distribuées, disponibilité et adaptabilité.

2. Qu’est-ce que NoSQL ?

2. Qu’est-ce que NoSQL ?

NoSQL signifie Not Only SQL : il complète le SQL, il ne le remplace pas. Pas de schéma rigide préétabli, donc une structure qui évolue vite : réseaux sociaux, streaming, e-commerce.

Flexibilité

Pas de schéma prédéfini : structures variées, intégration facile de nouvelles données, applications adaptables aux besoins changeants.

Scalabilité horizontale

Ajout de serveurs pour répartir les données et augmenter stockage et traitement, essentiel en cas de fort trafic.

Données non structurées

Documents (JSON, BSON), clé-valeur, colonnes, graphes : données issues des réseaux sociaux, capteurs IoT, contenus multimédias.

Performance et tolérance aux pannes

Conçues pour le distribué ; grâce à la réplication, le système continue si un ou plusieurs serveurs tombent, sans perte de données.

4. Graphes : Neo4j (Cypher)
Alice est amie avec Bob, Bob est ami avec Charlie, Alice suit Charlie.
CodeExplication
CREATE (:Personne {nom:'Alice'}), (:Personne {nom:'Bob'}), (:Personne {nom:'Charlie'});Crée 3 nœuds de type Personne avec une propriété nom.
MATCH (a:Personne {nom:'Alice'}), (b:Personne {nom:'Bob'}) CREATE (a)-[:AMI_DE]->(b);Trouve les deux nœuds puis crée l’arête AMI_DE (la flèche donne le sens).
MATCH (b:Personne {nom:'Bob'}), (c:Personne {nom:'Charlie'}) CREATE (b)-[:AMI_DE]->(c);Bob est ami avec Charlie.
MATCH (a:Personne {nom:'Alice'}), (c:Personne {nom:'Charlie'}) CREATE (a)-[:SUIT]->(c);Alice suit Charlie : un autre type de relation.
MATCH (:Personne {nom:'Bob'})-[:AMI_DE]-(ami) RETURN ami.nom;Qui sont les amis de Bob ? Sans flèche, le sens est ignoré.
MATCH (p)-[:SUIT]->(:Personne {nom:'Charlie'}) RETURN p.nom;Qui suit Charlie ?
MATCH (:Personne {nom:'Alice'})-[*1..3]-(autre) RETURN DISTINCT autre.nom;Personnes liées à Alice directement ou indirectement (1 à 3 relations) ; DISTINCT évite les doublons.
✔ À utiliser pour
  • Réseaux sociaux, recommandations d’amis ou de produits
  • Détection de fraude, chemins et itinéraires
  • Questions du type « qui est lié à qui, et à combien de degrés ? »
✘ À éviter pour
  • Statistiques et agrégats sur de gros volumes
  • Stockage simple de documents ou de journaux

4. MongoDB
4. MongoDB
MongoDB répond aux limites des bases relationnelles qui dominaient les années 1970-2000 : parfaites pour des structures fixes, mais peu adaptées aux données variées et volumineuses du web moderne.
5 caractéristiques
  • Documents JSON : informations complexes regroupées en un seul objet
  • Schéma flexible : structures variées dans une même collection
  • Scalabilité horizontale : le sharding répartit les données sur plusieurs serveurs
  • Haute disponibilité : la réplication garde des copies sur plusieurs nœuds
  • Hautes performances : opérations rapides, utile en temps réel


Collections et documents
  • Collection ≈ table
  • Document ≈ ligne, avec sous-documents et tableaux
  • Hiérarchie : base → collections → documents

5. Architecture
5. Architecture
Architecture client-serveur : le serveur mongod stocke les données et traite les requêtes ; les clients sont des applications, MongoDB Compass ou le MongoDB Shell.
Serveur autonome
Pour un petit volume ou la phase de développement : une seule instance mongod, ni sharding ni réplication, pas de mongos. Simple à configurer.
Architecture distribuée
Pour de grandes quantités de données ou la haute disponibilité : sharding et/ou réplication.
  • Sharded Cluster : chaque mongod ne contient qu’une partie des données
  • Replica Set : copies redondantes, continuité en cas de panne

Agrégation
Chaque étape reçoit le résultat de la précédente.
CodeExplication
db.etudiants.aggregate([Ouvre le pipeline : un tableau d’étapes exécutées dans l’ordre.

])Ferme le pipeline.

Valider avec $jsonSchema
Des règles au niveau de la collection garantissent la qualité des données : champs obligatoires, types corrects, plages de valeurs. MongoDB reste flexible, mais les données restent correctes.
Le mot-clé validator est toujours nécessaire à la création d’une collection avec règles.


db.createCollection("etudiants", {
 validator: { $jsonSchema: {
  bsonType: "object",
  required: ["nom", "moyenne"],
  properties: {
   nom: { bsonType: "string" },
   moyenne: { bsonType: "double",
     minimum: 0, maximum: 20 } } } } })

insertOne({ nom: "Amina", moyenne: 15 })  // OK
insertOne({ nom: "Ali",   moyenne: 25 })  // Erreur

Index commentés
Un index évite de parcourir toute la collection.
CodeExplication
db.etudiants.createIndex({ nom: 1 })Index simple croissant (1) sur nom : recherches rapides par nom.
db.etudiants.createIndex({ section: 1, moyenne: -1 })Index composé : section croissante puis moyenne décroissante ; l’ordre des champs compte.
db.etudiants.createIndex({ numero_inscription: 1 }, { unique: true })Index unique : deux étudiants ne peuvent pas avoir le même numéro.

db.etudiants.getIndexes()Liste les index existants de la collection.
db.etudiants.find({ nom: "Amina" }).explain("executionStats")Montre le plan d’exécution : IXSCAN = index utilisé, COLLSCAN = parcours complet.

À retenir : les index accélèrent les lectures mais ralentissent insertions et mises à jour. Évitez les index inutiles et testez avec find({ moyenne: { $gt: 10 } }).explain("executionStats").

Que signifie NoSQL ?

Quelle est la limite de la scalabilité verticale ?
Ajouter CPU/RAM à un seul serveur est coûteux et limité ; NoSQL préfère la scalabilité horizontale (ajout de serveurs).
Citez les 4 types de BDD NoSQL avec un SGBD pour chacun.

Pourquoi Redis est-il extrêmement rapide ?
Accès direct par la clé, sans jointure, et données stockées en mémoire (RAM).
Dans un graphe, que sont les nœuds et les arêtes ?
Les nœuds sont les entités (Alice, Bob) ; les arêtes sont les relations (« amie », « suit »).

Un serveur autonome : une seule instance mongod, sans sharding ni réplication.
Quels rôles jouent mongos et les Config Servers ?
Mongos est le routeur ; il consulte les Config Servers (métadonnées sur l’emplacement des données) pour diriger la requête vers le bon shard.
Quelle différence entre sharding et réplication ?
Le sharding répartit les données entre plusieurs serveurs (scalabilité) ; la réplication en conserve des copies (haute disponibilité).
