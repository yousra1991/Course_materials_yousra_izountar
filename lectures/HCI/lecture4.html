Where are we in the course?

This lecture sits in the design part of the course. You already know why we design around users. Now you learn the building blocks of a graphical interface and how to draw and simulate an interface before developing it.

1. IntroductionWhat HCI is, why it matters.
2. DesignUnderstand users, define needs (Double Diamond).
3. Mock-ups ← you are hereWidgets, mock-up types and tools, interactions.
4. EvaluationErgonomic audit and user tests on your mock-ups.

Key idea. A mock-up is the bridge between a design idea and something users can look at, click and judge.

Reminder: design methods

HCI design methods are user-centred, prototyped, evaluated early and iterative. Click a card to see what it means for mock-ups.

Definition

A mock-up is a partial, schematic visual representation of software that illustrates its appearance, structure and/or features — made BEFORE development.

Efficiency. Three rounds of mock-up and test are enough to remove most of the problems.

Mock-ups: why, for whom, when?

Remember. Draw early, test early, change cheaply. A wrong idea on paper costs minutes; in code it costs days.

Graphical widgets and WIMP

Widget = window gadget: a visual element of a graphical interface, often interactive. Examples: button, list, menu, scrollbar.

WIMP paradigm

Pick a letter.

Post-WIMP

Mobile and touch screens, innovative interactions (gestures, voice, 3D…).

A precise vocabulary matters

  • To communicate the project inside the team and with the client.
  • Designer words and user words differ. Example: designers say checkbox, a user label says “Tick to receive advice”.

Window vocabulary

Tap a part of the window to name it.

Active window and multi-windowing

  • Active window (has the focus) vs inactive window.
  • With overlap: some information is hidden; reaching a hidden window takes time (use the taskbar).
  • Without overlap: nothing is hidden. Windows are tiled, or one window is organised in blocks.

Application and document windows

Utility windows

Small windows that help the main one. Try each demo.

Floating window

Use: tool palettes, floating toolbars. Drag it.

Tooltip (help bubble)

Use: inform and help. Shows after about 0.5 s of hovering.

Contextual information

Use: offer tools useful here and now. Select some text.

Messages

Use: talk to the user. Four kinds.

Progress indication

Dialog windows

A dialog box is linked to an action of the user. It separates, in time and place, the specification of a command (fill the options) from its execution (press OK).

Vocabulary. The application window is the calling window; the dialog is the secondary window (also called pop-up).

Icons, menus and cursors

Small things that carry big meaning.

IconsObjects, actions, and the icon-not-logo rule.MenusDrop-down, contextual and pie menus.Menu characteristicsHierarchical and tear-off menus.CursorsOne pointer, many shapes.

Icons

An icon is an interactive graphic symbol. Tap an icon.

Usage

  • Give a direct access to frequent commands.
  • Often with a label.
  • Can be built into a button or a menu.
Careful: an icon is not a logo

A logo is a brand sign. An icon is something you can use.

Menus

A menu is a set of items: a list of commands triggered by a click. The chosen option is highlighted.

Drop-down menu

Opens from an entry point (the menu bar).

Contextual (pop-up) menu

Opens at the cursor position. Click in the area.

Pie menu (circular)

Menu characteristics

Hierarchical menu

A ▶ arrow shows a submenu. Use: group related sub-items.

Tear-off menu

Tear it off the dotted bar: the palette becomes a utility window.

Cursors

The cursor (pointer) is the visual mark of the position on screen or in a text. Its shape tells the nature of the action. Move your pointer over each box.

Pointing devices: mouse, trackball, joystick… (a touch screen has no cursor).

Paper mock-up: pros and cons

  • + Quick to change, shows the screen layout.
  • − Not to scale, no real content, not very evolutive, not realistic.

Mock-up tools

Why a dedicated tool? To concentrate on design and ergonomics, without being distracted by technical or development aspects.

Screen captures

Tools

  • Provided by the operating system, or additional tools.
  • Screen capture → shows the interface.
  • Screen recording → shows the interactions.

Integrating screens in a report

Do
  • One complete capture per screen.
  • Paste or import, then resize proportionally to the original window.
  • Keep the reading direction of the text.
Do not
  • Make several extracts of the same screen.
  • Cut the captures into pieces.
  • Retouch the image (brightness correction).
  • Rotate the screen.

Adapting the captures

Do not cut up captures. Use these five steps. Tap a number.

Annotating mock-ups

Place in the document

  • Integrate or separate from the text.
  • Align neatly.

Annotate legibly

  • Labels: numbers 1 2 3, or symbols (Wingdings), or Unicode characters: ①②③ ❶❷❸.
  • Check portability and legibility.
  • Arrows and connectors: not drawn by hand.

Write clear legends

  • Comments and remarks: same style as the home screen.
  • Legend text: no border, no background, sans-serif font, left-aligned (or centred).

How does a program wait for, and react to, the user?

Directive dialogueThe program leads; the user answers.Reactive dialogueBranches depend on the user's choice.Event-driven programmingThe system acts when events arrive.The event queueFirst in, first out.Events: triggersUser, timer or system.

Directive dialogue

Principle: the sequence of steps is fixed in advance. Treatment 1, then 2, then 3. Try it: answer the questions.

Program

Principle: the program can branch according to the answers of the user, then loop.

Event-driven programming


Principle: the system acts when events arrive. A loop keeps the system running, picks the next event and sends it to the right function.


Try the form
Click or type in the form.


Main loop




The event queue


The event queue manages the arrival and the execution of events. It is a FIFO queue: First In, First Out.






Events: triggers


Triggered by the user


  • Mouse / touch: double click, right click, click Click = MouseDown + MouseUp; moves MouseMove, Enter, Exit.

  • Keyboard: key press KeyPress = KeyDown + KeyUp, Enter; typing in a text zone Change.


Triggered by a timer (periodically)
  • Splash screen, screen refresh.


Triggered by the system
  • Drawing (a component becomes visible), activation (a window gets the focus), network request, a removable disk inserted…
