Question 1 — answer B

In this lab, why do we use MongoDB Atlas instead of installing the Community Server on every computer?

A. The Community Server is not free, so it cannot be used in a course
B. Atlas is a cloud platform: there is no server to install, upgrade or maintain  ✔
C. Atlas is the only edition that can store JSON-like documents
D. The Community Server cannot be used from the mongosh shell
Explanation: Atlas is a managed cloud platform: there is no server to install, upgrade or maintain. The Community Server is free, works with mongosh, and both editions store JSON-like documents.

Question 2 — answer D

You are connected to your Atlas cluster with mongosh and you run the command below. Which output proves that the connection works?

db.runCommand({ ping: 1 })
A. switched to db ping
B. { acknowledged: true, insertedId: null }
C. Nothing is printed when the connection works
D. { ok: 1 }  ✔
Explanation: A successful ping returns { ok: 1 }. “switched to db …” is printed by use, and { acknowledged: true, insertedId … } by an insert.

Question 3 — answer A

You type use univ for a database that does not exist yet, then show dbs. Why is univ not listed?

use univ
show dbs
A. A database is created only when it holds data, such as a collection or a document  ✔
B. use only works with existing databases, so the command failed
C. show dbs lists the system databases only
D. A database must first be created from the Atlas web interface
Explanation: A database is only really created once it holds data, for example when a collection is created or a document is inserted. use univ only switches to it, so it does not appear in show dbs yet.

Question 4 — answer C

You run the command below without providing an _id. What does MongoDB do?

db.students.insertOne({ name: "Amine", age: 22 })
A. It refuses the document because _id is mandatory
B. It stores the document without any identifier
C. It adds a unique _id field (an ObjectId) to the document automatically  ✔
D. It adds an integer _id that starts at 1 and auto-increments
Explanation: When no _id is given, MongoDB adds a unique ObjectId. There is no auto-incremented integer by default.

Question 5 — answer D

Which command inserts the two documents with a single call?

A. db.students.insertMany({ name: "Lina" }, { name: "Karim" })
B. db.students.insertOne([{ name: "Lina" }, { name: "Karim" }])
C. db.students.insertMany({ name: ["Lina", "Karim"] })
D. db.students.insertMany([{ name: "Lina" }, { name: "Karim" }])  ✔
Explanation: insertMany takes one array of documents. A passes two separate arguments, B uses insertOne with an array, C builds a single document with an array field.

Question 6 — answer B

What does this query return?

db.students.find({ city: "Alger" }, { name: 1, _id: 0 })
A. All the fields of the students whose name is 1
B. Only the name field of the students living in Alger  ✔
C. Only the _id and the name of the students living in Alger
D. Only the name field of all the students, whatever their city
Explanation: The filter keeps the students whose city is Alger. The projection { name: 1, _id: 0 } shows only the field name and hides _id.

Question 7 — answer A

Which students does this query return?

db.students.find({}, { name: 1, _id: 0 }).sort({ average: -1 }).limit(3)
A. The names of the 3 students with the highest averages  ✔
B. The names of the 3 students with the lowest averages
C. The names of the first 3 inserted students, sorted by name
D. The names of all the students, from the best average to the worst
Explanation: sort({ average: -1 }) orders from the highest average, limit(3) keeps the first 3, and the projection keeps only the names.

Question 8 — answer C

What happens when you run this command?

db.students.updateOne({ name: "Karim" }, { city: "Alger" })
A. The city of Karim is updated and his other fields are kept
B. The document of Karim is replaced by { city: "Alger" }
C. An error: the update document must use an update operator such as $set  ✔
D. Every student named Karim is updated
Explanation: The second argument of updateOne must use update operators such as $set (or be an aggregation pipeline). Without one, MongoDB raises an error; it does not replace the document (that is the job of replaceOne). Correct: { $set: { city: "Alger" } }.

Question 9 — answer B

The collection has 8 students, 5 of them in ASD. What does the result of this command show?

db.students.updateMany({ speciality: "ASD" }, { $inc: { average: 0.5 } })
A. matchedCount: 1 and modifiedCount: 1
B. matchedCount: 5 and modifiedCount: 5  ✔
C. matchedCount: 5 and modifiedCount: 0
D. matchedCount: 8 and modifiedCount: 5
Explanation: The filter matches the 5 ASD students and $inc adds 0.5 to each average, so the 5 documents are modified: matchedCount: 5, modifiedCount: 5. The 3 other students do not match.

Question 10 — answer D

No student is named Rayan. What happens when you run this command?

db.students.updateOne(
  { name: "Rayan" },
  { $set: { age: 24 } },
  { upsert: true }
)
A. Nothing happens: matchedCount and modifiedCount are 0
B. An error says that no document matches the filter
C. The first student of the collection is renamed Rayan
D. A new document is created from the filter and the $set fields (upsertedCount: 1)  ✔
Explanation: With upsert: true and no matching document, MongoDB inserts a new one built from the filter (name: "Rayan") and the $set fields (age: 24): matchedCount: 0, modifiedCount: 0, upsertedCount: 1.

Question 11 — answer A

What is the effect of this command?

db.students.deleteMany({})
A. It deletes every document of the collection; the empty collection remains  ✔
B. It deletes nothing: an empty filter matches no document
C. It deletes only the first document of the collection
D. It drops the students collection and removes it from the database
Explanation: The empty filter {} matches every document, so all of them are deleted. The empty collection remains: removing the collection itself is the job of drop().

Question 12 — answer C

This query returns the same students as which filter?

db.students.find({ city: { $in: ["Oran", "Annaba"] } })
A. { $and: [{ city: "Oran" }, { city: "Annaba" }] }
B. { city: { $nin: ["Oran", "Annaba"] } }
C. { $or: [{ city: "Oran" }, { city: "Annaba" }] }  ✔
D. { city: ["Oran", "Annaba"] }
Explanation: $in with a list of values is equivalent to $or on the same field. A matches nobody (no city is both Oran and Annaba), B is the opposite ($nin), D compares the city with a whole array and matches nothing.

Question 13 — answer B

The goal is to find the students aged from 23 to 25. Why is this query wrong?

db.students.find({ age: { $gte: 23 }, age: { $lte: 25 } })
A. $gte and $lte cannot be combined in the same query
B. The key age is repeated: only the last condition is kept, so every student aged 25 or less is returned  ✔
C. It is correct: it returns the students aged from 23 to 25
D. It returns only the students aged exactly 23 or exactly 25
Explanation: The key age is written twice in the same object: JavaScript keeps only the last one, so the query is just age ≤ 25. The correct filter is { age: { $gte: 23, $lte: 25 } }.

Question 14 — answer D

Which students (A, B, C, D) are returned by this query?

// A: ["NoSQL", "ML", "BI"]   B: ["NoSQL"]
// C: ["ML", "Web"]          D: ["BI"]
db.students.find({ modules: { $all: ["NoSQL", "ML"] } })
A. A, B and C
B. A and B
C. None, because the array must be exactly ["NoSQL", "ML"]
D. Only A  ✔
Explanation: $all requires every listed value to be in the array, in any order and with other elements allowed. Only A contains both NoSQL and ML: B lacks ML, C lacks NoSQL, D has neither.

Question 15 — answer A

Which students are returned by this query?

// Amine: scholarship: true      Samir: (no scholarship field)
// Sarah: scholarship: true      Sonia: scholarship: false
db.students.find({
  scholarship: { $exists: false },
  name: { $regex: "^S" }
})
A. Only Samir  ✔
B. Samir and Sonia
C. Samir, Sarah and Sonia
D. Amine and Samir
Explanation: $exists: false keeps the students without the field. Among the names starting with S, only Samir has no scholarship field: Sarah has true and Sonia has false, so the field exists for both. Amine does not start with S.
